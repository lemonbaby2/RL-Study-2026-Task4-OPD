General OPD
让学生在自己的轨迹上学习

On-Policy Distillation 不是新算法，而是把 RL 训练循环里的 reward 换成了一个冻结 teacher 的 logprob —— 它把「设计奖励函数」这件最需要人肉判断的事，降级成了「调一次前向」。

01 / 定位

两种失败模式，正好互补

按「轨迹从哪来」和「信号密度」两个正交维度切开后训练方法，OPD 恰好填上那个空位。

方法采样方式奖励信号每回合信息量代表
SFT / 离线蒸馏off-policy密集O(N) bitAlpaca、OpenThoughts-3
RL（PPO / GRPO）on-policy稀疏O(1) bitPPO、GRPO、DAPO
OPDon-policy密集O(N) bitGKD、MiniLLM、Tinker OPD
off-policy 的失败

状态分布偏移

学生学的是 teacher 常遇到的上下文，部署时走的却是自己的上下文。早期一个 teacher 从不犯的错，就让它漂出训练状态空间，误差按 O(εT²) 累积 —— 这就是 exposure bias（DAgger, 2010）。

on-policy RL 的失败

信号太稀

512 token 的推理只拿到一个 reward=0。它知道"这条路错了"，但不知道错在哪一步：运算顺序？算术？读题？功劳分配无法完成。

OPD 的解法

on-policy + 密集

保留 RL 的 on-policy 采样，把稀疏的 outcome reward 换成 teacher 的密集 token 级 logprob。等于老师坐在旁边给你自己下的每一步棋打分。

02 / 推导

从序列级 KL 到 token 级 advantage

教程在这里跳步最多。下面把每一步补齐 —— 其中「链接法则拆 token」是整篇的技术枢纽。

D_KL(π_θ ‖ π_T) = Ey~π_θ[ log π_θ(y|x) − log π_T(y|x) ]
期望采样自 π_θ —— 这就是 on-policy 的全部含义。取 π_T 就是前向 KL（mode-covering），那是 SFT 的目标。
↓　链式法则 log π(y|x) = Σt log π(yt|x,y<t)，再交换期望与求和
D_KL = Σt Ey~π_θ[ log π_θ(yt|x,y<t) − log π_T(yt|x,y<t) ] ≜ Σt E[ rtKL ]
关键：序列级 KL 变成 T 个 token 级项之和，每项只需要同一前序上下文下的两个 logprob。所以 teacher 只需一次前向，不必重新自回归生成 —— 这就是 OPD 比 RL 便宜的根本原因。
↓　取负作为 advantage
At = −β · rtKL
代码就两行：reverse_kl = student_lps − teacher_lps / advantages = −β * reverse_kl
情形含义advantage训练效果
student_lp > teacher_lp学生比老师更偏爱这个 token（可能是坏习惯）< 0压低该 token 概率 ✓
student_lp < teacher_lp老师更偏爱它（学生该学但没学到）> 0提高该 token 概率 ✓
两者相等学生已在该状态上与老师一致0不动

一个漂亮的等价关系：OPD ≡ RL(reward_t := −β·r_t^KL) —— 用 teacher 当逐 token 奖励模型的 RL。Thinking Machines 原文说得更直白：在已有的带 KL 正则的 RL 实现上，OPD 只是「把正则化所用的模型换掉」这一行的改动。

⚠️ 最容易误判的一点：单个 token 的 r_t^KL 可以为负。它只是两个数相减，只有对 student 完整分布取期望后 KL 才保证非负。日志里看到 reverse_kl_mean = −0.03，不等于公式失效。
03 / 实现

五个动作转圈

对应 01-demo-sync.py 的主循环。第 ③ 步是 OPD 与「假 OPD」的分水岭。

1
刷新 sampler严格 on-policy：用当前 student 权重采样。sampler_refresh_steps=1 最严格，调大就是引入 stale policy 偏差。
2
student 采样 completion每个 prompt 生成 group_size 条，同时保存每个 token 的 old logprob（后面 importance sampling 要用）。
3
teacher 给同一条轨迹打分拼 prompt_ids + completion_ids 送 compute_logprobs，一次前向、不生成，然后切掉 prompt 区间。这是心脏。
4
构造 reverse KL advantageA_t = −β · (student_lp − teacher_lp)，再把四个序列右移对齐成等长（prompt_loss_len = P−1，不是 P）。
5
importance_sampling 更新forward_backward() → optim_step()。用 π_now/π_old 比率修正批内参数漂移 —— 是工程方差控制，不是算法必需。
为什么 ③ 是分水岭：如果 teacher 自己重新生成一条答案再和 student 比，token 对不上、状态对不上，那就退回成了 off-policy 蒸馏，不是 OPD。
04 / 工程

七个陷阱：从「看起来能跑」到「真的学到了」

这是我读代码时标出来的、最容易让人白跑一晚的那些坑。

#陷阱症状修法
1tokenizer 不兼容KL 不降或乱跳同系列模型（Qwen↔Qwen）；跨系列需 DSKD 式双空间投影
2切片 off-by-oneKL 全程偏大，不明显断言 len(completion)==len(teacher_lps)
3右移对齐错位loss 抖、质量缓降保持四序列等长断言
4None 被静默吞掉KL 平稳但不降显式 any(v is None) 抛错
5stale policyKL 先降后升严格 OPD 设 refresh=1
6把 group_size 当 GRPO 的组写了组内归一化，信号变味OPD 里每条 completion 独立监督，没有 baseline
7单 token KL 为负就回滚反复改超参看多 step 趋势 + 长度 + 方差

第 6 条最容易概念混淆：GRPO 的 group_size 条回答要互相比较算组内相对优势 A_i=(r_i−mean)/std；OPD 的 group_size 只是「同 prompt 多采几条 on-policy 轨迹」，彼此完全不比较。搞混会写出完全错误的代码。

05 / 批判

OPD 不是银弹

读完 2026 年的腾讯 OPD 综述与 Rethinking 论文，补上教程没强调的四个边界。

失效模式 ①

多样性坍缩

反向 KL 是 mode-seeking，天然收缩到单一主峰，学生输出会变得高度同质。

失效模式 ②

错误前缀陷阱

学生一开头就错，teacher 在被污染的前缀上也可能给出误导性偏好，后续「纠正」已无意义。

失效模式 ③

自博弈饱和

teacher-free 的自蒸馏变体缺少外部新增信息，收益很快见顶。

失效模式 ④

校准-能力差距

KL 很低但正确率不涨：学到的是「风格与自信度」，不是「事实准确性」。这正是 off-policy 蒸馏老问题在 OPD 里的回声。

OPD 有效的两个必要条件

  • 师生推理模式兼容 —— 思维链风格差异过大时，teacher 在 student 轨迹上给不出有意义的偏好。
  • teacher 提供真正的新增能力 —— 如果它只是「同能力的更自信版本」，学生只能学到自信。

成本要算清

方法AIME'24GPU 小时相对成本

正确定位：有强 teacher、又烧不起 RL 时，OPD 性价比最高。反之——如果你没有合适 teacher，或任务本身有干净的环境 reward，OPD 未必划算。
